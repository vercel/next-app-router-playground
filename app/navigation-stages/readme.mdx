- `unstable_prefetch()` removes subsequent content from the shared App Shell. A link with `prefetch={true}` can put it back in a per-link prefetch.
- `unstable_navigation()` removes subsequent content from both prefetch stages, even when the link uses `prefetch={true}`.

# !!col

```tsx app/navigation-stages/_components/staged-product.tsx
async function ContentAfterPrefetch({ productId, example }) {
  // !mark
  await prefetch();
  const sessionId = (await cookies()).get('session-id')?.value ?? 'guest';
  return (
    <>
      <Suspense fallback={<RecommendationsSkeleton />}>
        <MoreProducts sessionId={sessionId} example={example} />
      </Suspense>
      <Suspense fallback={<RecommendationsSkeleton />}>
        <ContentAfterNavigation productId={productId} sessionId={sessionId} />
      </Suspense>
    </>
  );
}

async function ContentAfterNavigation({ productId, sessionId }) {
  // !mark
  await navigation();
  const products = await getSessionRecommendations(productId, sessionId);
  return <Recommendations products={products} />;
}
```

</Grid>

Both APIs run outside the cached data functions. `MoreProducts` depends on a cookie, not URL data, and uses a private cache. The recommendations after the navigation gate are cached too.

### Demo

- `<Link>` includes only the product. More products and recommendations stream after navigation.
- `<Link prefetch={true}>` includes the product and more products in the prefetch. Recommendations still stream after navigation.
- Each data function includes an artificial delay to make the stages visible. Prefetching only runs in production.

### Notes

- This demo uses the experimental `unstable_prefetch()` and `unstable_navigation()` APIs.

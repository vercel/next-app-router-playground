- `unstable_prefetch()` excludes subsequent content from the shared App Shell. A `<Link prefetch={true}>` can still include it in a per-link prefetch.
- The **await prefetch** example uses this to prefetch its recommendations before navigation.

# !!col

```tsx app/prefetch-stages/prefetch/page.tsx
async function PrefetchedRecommendations() {
  const sessionId = (await cookies()).get('session-id')?.value;
  // !mark
  await prefetch();
  return getSessionRecommendations('1', sessionId ?? 'guest');
}
```

# !!col

- `unstable_navigation()` excludes subsequent content from both the shared App Shell and per-link prefetches.
- The **await navigation** example uses the same product page, but its recommendations start loading only after navigation.

# !!col

```tsx app/prefetch-stages/navigation/page.tsx
async function NavigationRecommendations() {
  const sessionId = (await cookies()).get('session-id')?.value;
  // !mark
  await navigation();
  return getSessionRecommendations('2', sessionId ?? 'guest');
}
```

</Grid>

Both stage APIs run outside the cached data function. Content below either gate remains cacheable.

### Demo

- Both examples use `<Link prefetch={true}>` and the same product-details and recommendations layout.
- In **await prefetch**, the product details and recommendations are ready when navigation starts.
- In **await navigation**, only the product details are ready. The recommendations show their fallback and stream in after navigation.
- Each data function includes an artificial delay to make the stages visible. Prefetching only runs in production.

### Notes

- This demo uses the experimental `unstable_prefetch()` and `unstable_navigation()` APIs.

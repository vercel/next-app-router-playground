# !!col

- With `partialPrefetching: true` (this playground's default), a `<Link>` prefetches the App Shell of its destination, not the page render. The shell is loaded once per filesystem route and shared across every `<Link>` to that route.
- `<Link prefetch={true}>` upgrades that link to also prefetch the cached page render.
- A route can export `unstable_prefetch = 'force-runtime'` to opt every visible link to it into a runtime prerender — a server-side prerender that resolves cookies, headers, and search params at prefetch time, ahead of the click.

# !!col

```ts next.config.ts
// !mark
const nextConfig = {
  cacheComponents: true,
  // !mark
  partialPrefetching: true,
};
```

```tsx app/partial-prefetching/page.tsx
import Link from 'next/link';

// A: shell only
<Link href="/cached" />;

// B: shell + cached page content
// !mark
<Link href="/cached" prefetch={true} />;

// C: shell only (Suspense fallback paints on click)
<Link href="/streaming" />;

// D: runtime prerender
// !mark
// (route exports unstable_prefetch = 'force-runtime')
<Link href="/runtime" />;
```

### Demo

- Open DevTools → Network and filter on `_rsc=`.
- Each link contributes a small route-tree prefetch when it enters the viewport.
- Links B and D additionally fetch a larger payload that includes the destination's content.
- Link A produces no second payload because the destination is fully cached: the shell already covers everything.
- Click each link and notice whether the body appears instantly (A, B, D) or behind a fallback (C).

### Notes

- All four `<Link>`s share the same App Shell prefetch per destination route. Render dozens of them on a page and the network cost grows by route, not by link.
- `unstable_prefetch = 'force-runtime'` costs one server invocation per visible link to the route. Reach for it only when the prefetched content is worth the cost.

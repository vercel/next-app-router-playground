# !!col

- With `partialPrefetching: true` (this playground's default), a default `<Link>` only prefetches the App Shell of its destination.
- `<Link prefetch={true}>` upgrades the prefetch to include the destination's cached page content alongside the shell.
- A route can export `prefetch = 'allow-runtime'` to opt every visible link to it into a runtime prerender that resolves cookies, headers, and search params at prefetch time.

# !!col

```ts next.config.ts
// !mark
const nextConfig = {
  cacheComponents: true,
  // !mark
  partialPrefetching: true,
};
```

```tsx app/partial-prefetching/page.tsx
import Link from 'next/link';

// App Shell only
<Link href="/streaming" />;

// App Shell + cached page content
// !mark
<Link href="/cached" prefetch={true} />;

// Runtime prerender (route opts in)
<Link href="/allow-runtime" />;
```

### Demo

All three destinations render the same four sections:

- **Static** &mdash; pure, deterministic, always in the shell.
- **Cached** &mdash; `'use cache'` keyed by `?id`, shared across visitors.
- **Private cache** &mdash; `'use cache: private'`, per-user, cached in the browser.
- **Uncached** &mdash; reads `connection()`, fresh on every request.

The hub links pass a distinct `?id` to each destination so the `'use cache'`
section actually depends on a runtime value. Without that, the cached
content is free to live in the shell — and the difference between `<Link>`
and `<Link prefetch={true}>` is invisible.

Each section has a 2&nbsp;second delay so you can see what arrives in the prefetch and what streams in after the click.

Open DevTools &rarr; Network and filter on `_rsc=` to watch the prefetches as each card enters the viewport. Then click through and notice which sections paint instantly and which fall back to the streaming placeholder.

### Notes

- Routes are distinct (`/streaming`, `/cached`, `/allow-runtime`) so each gets its own App Shell entry.
- The hub passes `?id=1`, `?id=2`, `?id=3` so the `'use cache'` section's key is runtime-dependent. That's what makes the prefetch differences observable.
- The page exports use `unstable_prefetch = 'force-runtime'` in this canary build. The stable name (post-stabilization) will be `prefetch = 'allow-runtime'`.
